# 收藏转知识 · Collect to Knowledge

**简体中文** · [English](README.en.md)

把“收藏了，以后再看”变成“理解了，可以用”。

一个给 AI 助手使用的可复用 Skill：将社交媒体、播客、视频、博客和个人摘录，
整理成有来源、有生活应用、有下一步行动的知识卡片，并可按主题保存到**你自己的 Notion**。

> 这是工作流技能，不是独立 App。它依赖 AI 助手提供的阅读、文件、图片生成和
> Notion 连接能力；音视频转录可接入独立的本地转录工具。

## 能实现什么

| 输入 / 需求 | 输出 |
| --- | --- |
| 可访问的文章、帖子、粘贴文本、截图 | 核心观点、适用条件、来源说明 |
| 有字幕或能成功转录的播客 / 视频 | 基于实际内容的知识整理，标注覆盖范围 |
| “这对我的生活有什么用？” | 生活应用、明确标记的假设案例、最小下一步 |
| “给我一个执行方案” | 可检查的行动清单，适合时提供 3–7 天实验 |
| “做成图片卡片” | 简洁的视觉知识卡片 + 可编辑文字版，需图片生成能力 |
| “存到 Notion 并分类” | 去重、主分类、标签、来源链接；图片与文字放在同一条目 |
| 同一材料有新内容 | 更新已有条目，保留用户笔记和行动状态 |

典型流程：

**链接 / 文件 → 读取或转录 → 提炼知识 → 生活应用 → 执行方案 → 图片卡片（可选）→ Notion 分类归档（可选）**

## 快速开始

### 1. 安装 Skill

在 Codex 中把这句话发给 AI：

```text
使用 skill-installer 安装 https://github.com/Kylie08ky/collect-to-knowledge。
SKILL.md 位于仓库根目录，技能目录命名为 collect-to-knowledge。
如果已经安装，请先检查现有版本，保留我的本地配置，不要直接覆盖。
```

也可以下载仓库，将整个文件夹命名为 `collect-to-knowledge`，
放到你的 AI 工具支持的技能目录中。Codex 的技能安装器会使用
`$CODEX_HOME/skills`，未设置时使用 `~/.codex/skills`。
安装完成后在下一轮对话使用；未被识别时可新开聊天。

其他能读取 `SKILL.md` 的助手可以参考本技能，但工具名称、安装位置和权限流程
以对应产品为准。本项目主要在 Codex 中验证，不承诺所有助手开箱即用。

### 2. 首次配置你自己的 Notion

先在 AI 工具里连接 Notion，并让连接具备目标页面的访问权限，然后发送：

```text
使用 $collect-to-knowledge，先帮我完成首次配置。

我的 Notion 目标页面是：【粘贴你自己的 Notion 页面链接】。
我希望在该页面下建立按主题分列的知识库。
分类：心理、哲学、经济理财、健康、成长学习、科技工具、生活方式、待分类。
以后我交给这个技能的内容，请自动生成中文文字知识卡片和一张图片卡片，
包含生活应用和执行方案，并归入对应主题。
请把目标和偏好保存在本地 config.local.json，不要上传到 GitHub。
```

AI 会读取目标、确认它是普通页面还是数据库，并按你的要求配置。
已有合适的数据库可以直接使用，不需要新建。
**没有设置目标时，技能会先问你要保存到哪个页面。**

你也可以选择：
- **先预览再保存**：把“自动保存”改为“每次先给我预览，确认后再保存”。
- **不使用 Notion**：说“只在聊天或本地输出，不需要 Notion”。
- **只要文字**：说“默认不生成图片”。

公开仓库只提供空白 `config.example.json`。真实页面地址、数据库 ID、
保存偏好放在安装目录的 `config.local.json`，已加入 `.gitignore`。
连接凭据交给 AI 工具的 Notion 集成管理，不放进配置或聊天。

### 3. 开始使用

```text
$collect-to-knowledge
整理这个链接：【链接】
提炼核心内容、生活应用和执行方案，并按我的配置保存。
```

也可以直接说：

> 收藏转知识：【链接】。做成文字和图片卡片，按主题存入 Notion。

## 常用调用示例

```text
把这期播客整理成知识卡片，标出重要观点的时间位置。
【链接】

整理这条小红书，结合“每天只有15分钟”的情况设计行动方案。
【链接】

把这篇文章归入“哲学”，重点保留论证和适用边界。
【链接】

处理这三个链接，分别整理、去重、分类入库。
【多个链接】

先整理这段内容给我看，暂时不要保存到 Notion。
【文本】
```

不需要每次手动调用转录工具；可用时，主技能会根据输入选择对应流程。
“不要存”“只要文字”等当次指令优先于已保存偏好。

## 播客与视频：可选转录能力

推荐单独安装 [hotcatty/media-transcriber](https://github.com/hotcatty/media-transcriber)，
按其当前说明准备 Python、FFmpeg 和本地语音模型。它列出的平台包括小宇宙、
B 站、小红书视频、YouTube、苹果播客和本地音视频。

```text
请按 https://github.com/hotcatty/media-transcriber 的当前说明，
安装本地转录技能并接入 collect-to-knowledge。
先检查我的系统和依赖，使用独立环境；保留本地转录方式。
```

- 本地语音识别路线不需要 DashScope Key，模型和依赖需另外下载。
- Windows 的环境和 GPU 库需要适配，不能直接套用 Unix 虚拟环境路径。
- 小红书**纯图文**走正文 / 图片读取，不走语音识别。
- 登录、失效链接、平台限制、下载器变化都可能导致解析失败。
- 已在开发环境实测一条小宇宙播客和一条小红书视频；不是对所有链接的兼容承诺。
- 自动转录可能有错字、专名和数字误差，会明确标注。
- 可选的小宇宙元数据 / 官方转录助手：[weisi-gu/xiaoyuzhou-podcast-notes](https://github.com/weisi-gu/xiaoyuzhou-podcast-notes)。
  其云端后端需另行配置与授权，本技能不会自动切换付费服务。

详见 [媒体处理说明](references/media.md)。

## Notion 会怎样组织

在你要求建立分类知识库时，可设置：
**名称、主分类、标签、来源类型、来源链接、整理日期**，以及主题看板和分类入口。

一条来源通常是一页，页内包含文字卡片、图片和行动方案。
跨主题用标签补充，不在多个栏目重复创建同一条目。
已有数据库会读取真实字段并映射，不要求你使用固定的中文字段名。

## 隐私与限制

- **没有任何作者的 Notion 页面或数据库配置。** 每位用户自行选择目标。
- 默认保存模式为先询问；自动保存需要用户明确选择。
- 只处理你交给技能的材料，不自动扫描所有收藏或后台监控。
- 本地 ASR 不等于整条工作流离线：内容仍由你使用的 AI 助手处理；
  获准保存的摘要和图片会发送到 Notion。
- 不上传原始媒体、Cookie、密钥、私人文字稿或本地配置到 GitHub。
- 不会把摘要冒充完整转录，不会把助手设计的案例写成作者原话。
- 不打包第三方完整内容；对第三方版权材料交付原创提炼与必要短引。
- 图片生成、Notion 写入和转录都依赖相应能力；失败时会说明哪个步骤未完成。
- AI 服务、图片生成和可选云端服务的费用遵循各自服务规则。
